# Art Media Publishing Site

[简体中文](README.md) | [繁體中文（香港）](README.zh-HK.md) | [繁體中文（臺灣）](README.zh-TW.md) | [日本語](README.ja.md) | [English](README.en.md)

## このプロジェクトについて

Node.js、Express、SQLite、EJS で構築された作品展示・メディア公開プラットフォームです。写真、動画、テキストなど多様な形式に対応し、管理画面からの公開ワークフロー、画像バリアント生成、動画トランスコード機能を備えています。

## なぜこのプロジェクトを作ったのか

私は創作愛好家です。

このシステムを作ったきっかけは、商用プラットフォームの硬直的な表示方式（3x3のグリッドか1:1しか選べない）に対する不満と束縛感、そして主流のアート界が「何がアートか」という定義を独占し、そこから派生する個人クリエイターへの排除に対する無念さでした。

そこで私は AI の支援を受け、このシステムを構築しました。当初は私個人の使用と表示習慣に基づいて設計されたものでしたが、今ではオープンソースとして公開します。アルゴリズムと学術的独占に苦しむ個人クリエイターが、自分だけの「ホワイトキューブ」を持ち、「芸術作品は特定の機関に依存しなければ展示できない」という物語を解体できることを願っています。

私は正規のソフトウェアエンジニアではなく、基本的なサーバー運用経験しか持っていないため、現在のシステムをさらに最適化・拡張することはできないかもしれません。しかし、このプロジェクトにニーズや共感を持つ方が fork または利用して、自分のニーズを満たすことを大いに歓迎します。

Issues については、できる限り返信しますが、解決を約束することはできません。

PR については、提出されたコードをできる限り理解するよう努めますが、受け入れることを約束することはできません。どのような変更をしたかを詳しく教えていただければ、非常に感謝します。

## 特徴

### 公開サイト
- ホームページ、コレクション一覧、拡大画像ビューア、作品解説表示
- Lightbox 表示：すべての表示モード（single/diptych/wall/report/anthology/archiving）で画像クリック時に Lightbox オーバーレイで拡大表示（新ページ遷移なし）；左右ナビゲーション、キーボード操作（Esc で閉じる、← → で切替）、オーバーレイクリックで閉じる；diptych モードではペア画像を並べて表示（モバイルでは縦積み）；下部に作品解説を Markdown レンダリング
- 第5の表示モード「アンソロジー（anthology）」：コレクションのトップページは Grid グリッドで複数のアンソロジー入口を表示（各メディアブロックが1つのアンソロジーに対応し、ブロックの最初の画像がサムネイルになります）；入口をクリックするとそのアンソロジーのサムネイルページに移動；各アンソロジーは個別にタイトルを設定でき、タイトルはサムネイルの下に表示されます；Grid レイアウトはフィルム「コンタクトプリント」（Contact Printing）スタイルを採用し、固定比率のセルを統一配置
- 第6の表示方式「アーカイブ（archiving）」：アンソロジーと同様に複数のメディアブロックとステートメントブロックをサポートしますが、1階層目のページはタイトルリスト形式で表示され（サムネイルグリッドではなく）、タイトルはメディアブロックの「アンソロジータイトル」とステートメントブロックの「ドキュメントタイトル」から取得します；タイトルをクリックすると対応するブロックの2階層目のページに進み、下部に「戻る」リンクがあります
- anthology と archiving のメディアブロックで「画幅/表示方式」を選択可能：フィルム画幅比率（3:2/135、2:3/Half、2.7:1/X-Pan、4:3/6x4.5、1:1/6x6、1.16:1/6x7、1.37:1/6x8、2.25:1/6x12、3:1/6x17、5:4/4x5）と表示方式（シングル single、ディプティク diptych、フォトウォール wall、レポート report）の2つの次元をサポート；サブページ（`/:slug/:blockId`）と大画像ページ（`/:slug/:filename_large?block=:id`）はブロックレベルの表示方式に従ってレンダリングされ、画幅比率はシングル表示方式下でのセル比率と縦長画像の回転にのみ影響；他の表示タイプは対応する表示方式に固定で選択不可

### 管理画面
- ログイン認証、ユーザー管理、ホームページ素材管理、コレクション管理
- メディアアップロード、並べ替え、下書き・公開ワークフロー
- アーティストステートメントテキストボックスで画像/動画を直接アップロード可能：アップロード後 `content/media_library/` に保存し、sharp/ffmpeg で処理後、カーソル位置に Markdown 参照を自動挿入；どのテキストボックスからも参照されていないファイルは自動クリーンアップ
- ブロックベースのコンテンツ編集：アーティストステートメントブロックとメディア管理ブロックを独立表示、折りたたみ可能、ドラッグで並べ替え、「上のレイヤー/下のレイヤー」ボタンで順序調整；各メディアブロックで個別に画像/動画をアップロード可能
- メディアブロックとテキストブロックの設定エリアを統一：どちらも「設定パネル（タイトル + 画幅/表示方式 + アップロードエリア）→ メイン編集エリア → 下部アクションバー」の3段構成；テキストブロックの画幅/表示方式は「テキストモード下では選択不可」に固定で無効化、「テキストを保存」ボタンはメディアブロックの「並び順を保存」ボタンと位置を揃える

### コレクション表示制御
| スイッチ        | 効果                                              |
| ----------- | ----------------------------------------------- |
| **エントリ非表示** | コレクションが公開ナビゲーションに表示されない                         |
| **アクセスブロック** | コレクションの slug ページ、拡大画像ページ、関連 API が 404 を返す（エントリ非表示が自動連動） |
| **情報非表示**   | フッターの完全なサイト情報を非表示                               |
| **短い署名表示**  | 情報非表示の時のみ有効；`shortSignature` テキストを表示            |

### メディア処理
- **画像処理**：Sharp による `thumb`、`medium`、`large` バリアントの自動生成、およびオリジナル画像の圧縮最適化
- **動画トランスコード**：FFmpeg による H.264/AAC MP4 自動トランスコード、1080p に圧縮、プログレッシブ再生対応

### システム設定
- サイト名、署名、ICP番号、ソーシャルリンク、画像/動画処理パラメータ
- すべてオンラインで変更可能、保存後すぐに反映、再起動不要

### 多言語対応（i18n）
- **フロント**：ブラウザの `Accept-Language` に基づいて自動的に言語をマッチング（簡体字中国語、繁体字中国語、英語、日本語）
- **管理画面**：システム設定で言語を指定可能

### その他の特徴
- **CDN サポート**：`CDN_URL` を設定すると、メディア URL に CDN プレフィックスが自動付与
- **セキュリティ**：CSRF 保護、CSP/HSTS ヘッダー、IP ベースのブルートフォースロックアウト、カスタム例外クラス
- **アクセスログ**：公開ページの IP/パス/タイムスタンプを自動記録、上限超過で自動クリーンアップ
- **セッション永続化**：セッションは SQLite に保存、サーバー再起動後もログイン状態を維持
- **グレースフルシャットダウン**：接続追跡、ヘルス/レディネスチェック、404/500 フォールバック
- **自動テスト**：91 の統合テスト + 11 のユニットテスト、コアワークフロー、セキュリティ、エッジケースをカバー、anthology / archiving サブルーティングとブロックレベルの `media_format` レンダリングを含む

## コレクション表示スタイルガイド

このシステムには 6 種類のコレクション表示スタイルがあります。大きく次の 2 種類に分けられます。

- **直接表示型**：シングル、ディプティク、フォトウォール、レポート
- **階層型**：アンソロジー、アーカイブ

### すぐに選ぶ

| スタイル | 表示の特徴 | おすすめの用途 |
| --- | --- | --- |
| **シングル（single）** | 元の比率を保ち、間隔のあるウォーターフォール表示 | 写真、絵画、イラストなど一般的な作品集 |
| **ディプティク（diptych）** | メディアの順番に従って 2 作品ずつ組み合わせる | 対比、呼応、前後関係、ペア作品 |
| **フォトウォール（wall）** | 複数列で隙間なく連続表示 | 作品数が多く、密度や全体の雰囲気を重視するシリーズ |
| **レポート（report）** | 画像ギャラリーとテキストブロックを組み合わせる | プロジェクト記録、展示報告、リサーチ作品 |
| **アンソロジー（anthology）** | まずカバーのグリッドを表示し、各シリーズへ移動 | 1 つのコレクションに複数の視覚シリーズがある場合 |
| **アーカイブ（archiving）** | まずタイトル一覧を表示し、各内容へ移動 | 年代別整理、文献、原稿、プロジェクト資料 |

迷った場合は次の基準を使ってください。

- 特別な構成がない：**シングル**
- 2 作品を必ず一緒に見せる：**ディプティク**
- 大量の画像で全体的なインパクトを出す：**フォトウォール**
- 作品と説明を一緒に見せる：**レポート**
- 複数のシリーズをカバー画像から見せる：**アンソロジー**
- タイトル、年代、文書名から探せるようにする：**アーカイブ**

### 6 種類のスタイル

#### 1. シングル（single）

各作品を独立して表示し、元の縦横比を保ったまま、間隔のある複数列のウォーターフォールに配置します。大画面では通常 3 列、中画面では 2 列、スマートフォンでは 1 列です。

作品同士に明確なペア関係がなく、1 点ずつ見せたい場合に適しています。「シングル」は 1 ページに 1 枚しか置けないという意味ではありません。

#### 2. ディプティク（diptych）

管理画面のメディア順に従って自動的にペアを作ります。1・2 枚目、3・4 枚目という単位で組み合わされ、枚数が奇数の場合は最後の 1 枚が単独で表示されます。

大画像表示でも 1 ペアを 1 単位として扱い、モバイルでは上下に積み重ねます。先にペアを決めてからメディア順を調整してください。1 枚を追加・移動すると、後続のペアが変わる可能性があります。

#### 3. フォトウォール（wall）

画像を隙間のない複数列で連続表示します。大画面では通常 4 列、中画面では 3〜2 列、スマートフォンでは 1 列です。動画はフォトウォール上でミュートされた状態で自動ループ再生されます。

全体のリズムと密度を重視する場合に適しています。大きな余白、作品ごとの読解、厳密なペア表示には向きません。

#### 4. レポート（report）

画像ブロックとテキストブロックを複数組み合わせて、「プロジェクト紹介 → 画像グループ → 制作過程 → 画像グループ → まとめ」のように構成できます。画像が少ない場合は枚数に応じて列数が決まり、多数の画像は通常正方形のギャラリーサムネイルとして表示されます。

テキストブロックは Markdown に対応し、画像や動画をアップロードして本文へ挿入できます。展示記録、制作研究、レジデンス、パフォーマンスなど、背景説明が必要な作品に適しています。

#### 5. アンソロジー（anthology）

2 階層構造です。1 階層目に複数のカバー入口を表示し、カバーをクリックすると対応するサブシリーズへ移動します。各メディアブロックは 1 つのサブシリーズに対応します。

- ブロック内の最初のメディアがカバーになります
- 「アンソロジータイトル」がカバーの下に表示されます
- メディアのないブロックは入口になりません
- テキストブロックはカバー入口にならず、トップページのグリッドの後に表示されます

各メディアブロックにタイトルを付け、カバーにしたい作品を先頭に置くことが重要です。

#### 6. アーカイブ（archiving）

アンソロジーと同じく 2 階層ですが、1 階層目にはカバーではなくタイトル一覧を表示します。メディアブロックは「アンソロジータイトル」、テキストブロックは「ドキュメントタイトル」を使います。タイトルのないブロックは一覧に表示されません。

年代、プロジェクト、メディア、文書名などから探す資料集に適しています。アンソロジーとの違いは、**アンソロジーはカバーで探し、アーカイブはタイトルで探す**ことです。

### アンソロジーとアーカイブのブロック設定

アンソロジーとアーカイブでは、メディアブロックごとに「画幅/表示方式」を設定できます。これはコレクション全体のタイプとは別の、ブロック単位の設定です。

表示方式は次の 4 種類です：シングル（single）、ディプティク（diptych）、フォトウォール（wall）、レポート（report）。

画幅は `3:2 (135)`、`2:3 (Half)`、`2.7:1 (X-Pan)`、`4:3 (6x4.5)`、`1:1 (6x6)`、`1.16:1 (6x7)`、`1.37:1 (6x8)`、`2.25:1 (6x12)`、`3:1 (6x17)`、`5:4 (4x5)` から選べます。

表示方式を選ぶと、サブページはそのレイアウトで表示されます。画幅を選ぶと、サブページは統一比率のコンタクトプリント風グリッドになります。画像の向きが画幅と合わない場合、システムが自動回転することがあります。

### 管理画面での作成と公開

1. 管理画面で名前、Slug、コレクションタイプを入力して作成します。新しいコレクションは初期状態で入口が非表示です。
2. 「メディア管理」を開きます。画像ブロックとテキストブロックが自動作成されています。
3. 画像ブロックに画像または動画をアップロードし、メディア順をドラッグして調整します。新しくアップロードしたメディアはブロックの先頭に入ります。
4. テキストブロックを編集します。Markdown に対応し、メディアをアップロードして本文へ挿入できます。
5. アンソロジーまたはアーカイブでは、各ブロックにタイトルを付け、メディアブロックの画幅または表示方式を設定します。
6. ブロックをドラッグするか「上へ/下へ」ボタンでページ順を調整します。
7. 「更新を公開」を押して、メディア、テキスト、タイトル、画幅、並び順をフロントへ反映します。
8. `/<slug>` でページを確認し、問題がなければコレクションカードの「入口を表示」を有効にします。

シングル、ディプティク、フォトウォールは通常 1 つのメディアブロックを使います。レポート、アンソロジー、アーカイブでは複数のメディアブロックを追加できます。すべてのタイプで複数のテキストブロックを追加できます。

### 公開、アクセス、大画像表示

- **入口を非表示**：公開ナビゲーションに表示されませんが、URL を知っていればアクセスできます。
- **アクセスをブロック**：コレクション URL、大画像ページ、関連 API が 404 を返し、外部アクセスを停止します。
- **更新を公開**：メディア、テキスト、ブロックタイトル、画幅、並び順は公開後にフロントへ表示されます。
- **コレクションタイプの変更**：タイプ変更は直接フロントへ反映され、コレクション内部の下書き公開操作は必要ありません。

既存のコレクションタイプを変更しても内容は削除されませんが、ブロック構成が新しいスタイルに合わなくなる場合があります。特にアンソロジー、アーカイブ、レポートからシングル、ディプティク、フォトウォールへ変更した場合は、必ずフロントを確認してください。

直接表示ページとアンソロジー/アーカイブのサブページでは、作品をクリックして Lightbox で大画像を表示できます。左右ボタンまたは方向キーで切り替え、`Esc` で閉じ、オーバーレイをクリックして戻ります。作品解説は大画像の下に表示されます。

## 動作要件

- Node.js `>= 18.17`
- npm `>= 9`
- FFmpeg と FFprobe：`npm install` 時に自動でバイナリがダウンロードされます（`ffmpeg-static` と `@ffprobe-installer/ffprobe` 経由）。手動インストールは不要です。システムにインストール済みのバージョンを使用する場合は、`FFMPEG_PATH` / `FFPROBE_PATH` 環境変数で指定できます

## クイックスタート

### ワンクリック起動（推奨）

macOS / Linux：
```bash
./start.sh
```

Windows：
```cmd
start.bat
```

起動スクリプトは以下の操作を自動で行います：
1. Node.js バージョンの確認（未インストール時はインストール方法を案内）
2. `.env` の自動作成（`.env.example` テンプレートから生成、ランダムシークレット付き）
3. 依存関係の自動インストール（`npm install`）
4. FFmpeg/FFprobe の利用可能性を検出
5. サーバーの起動

### 手動手順

1. 依存関係のインストール
```bash
npm install
```
2. サーバーの起動
```bash
npm start        # 本番環境
npm run dev      # 開発環境
```

> `.env` ファイルは初回起動時に `.env.example` から自動作成され、ランダムシークレットが生成されるため、手動コピーは不要です。

デフォルト：`http://localhost:3000`

管理画面ログイン：`http://localhost:3000/admin/login`

デフォルト管理者アカウント：`admin` / `admin`

## デプロイ

### 本番環境チェックリスト

- リバースプロキシ（Nginx / Caddy）を使用し、`TRUST_PROXY=true` を設定
- SSL/TLS 証明書を設定し、HTTPS を有効化（[Let's Encrypt](https://letsencrypt.org/) で無料取得可能）
- プロセスマネージャー（PM2 / systemd）を使用し、異常終了後の自動再起動を確保
- `.env` の `SESSION_SECRET` を強力なランダム値に変更
- 初回ログイン後、デフォルトの管理者パスワードを直ちに変更
- 定期的なバックアップ：SQLite データベース、`content/` ディレクトリ、`.env` 設定ファイル

### PM2

```bash
pm2 start server.js --name art-media-publishing-site
pm2 save
pm2 startup
```

### systemd

```ini
[Unit]
Description=Art Media Publishing Site
After=network.target

[Service]
Type=simple
User=your-user
WorkingDirectory=/var/www/art-media-publishing-site
Environment=NODE_ENV=production
ExecStart=/usr/bin/node /var/www/art-media-publishing-site/server.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

### Nginx リバースプロキシ

以下は HTTP の例です。本番環境では Nginx 側で HTTPS を設定してください（`certbot` で証明書を自動管理できます）。

```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        client_max_body_size 350m;
    }
}
```

## 既知の制限

- セッションは SQLite に永続化、マルチインスタンス共有には追加の対応が必要
- メディアはローカルファイルシステムに保存、クラウドオブジェクトストレージにはさらなる抽象化が必要
- 動画処理は `ffmpeg`/`ffprobe` に依存、`npm install` 時にバイナリが自動ダウンロードされます。システムにインストール済みのバージョンも使用可能、または `FFMPEG_PATH`/`FFPROBE_PATH` 環境変数でパスを指定
- CDN 有効化後、Nginx 設定の変更時は CDN キャッシュの手動リフレッシュが必要
