# Art Media Publishing Site

[简体中文](README.md) | [繁體中文（香港）](README.zh-HK.md) | [繁體中文（臺灣）](README.zh-TW.md) | [日本語](README.ja.md) | [English](README.en.md)

## 关于这个项目

这是一个基于 Node.js、Express、SQLite 和 EJS 的作品展示与媒体发布平台。支持图片、视频、文字等多种形式，包含完整的后台发布工作流、图片变体生成和视频转码能力。

## 为什么会有这个项目

我是一名创作爱好者。

构建这个系统的初衷，起初是因为我自身对商业平台僵硬的展示方式（不是九宫格就是1:1）感到不满和束缚，同时也对于主流艺术界对“什么是艺术”这一定义的垄断，以及由此衍生出的对个人创作者的排挤感到无奈。

于是我通过 AI 的协助，构建了这个系统。起初这只是根据我个人的使用和展示习惯进行设计的东西，但我现在将其开源，希望各位同样苦于算法和学术垄断的个人创作者都能拥有属于自己的“白盒子”，解构“艺术作品必须依附于特定机构才能呈现”的叙事。

由于我本人并非科班出身的软件工程师，仅具备基本的服务器运维经验，所以我可能没有办法对当前系统进行进一步的优化或扩展。但我非常欢迎各位对此有需求或共鸣的朋友fork或使用这个项目，以满足自己的需求。

对于Issues，我会尽可能回复，但不能承诺能够解决。

对于PR，我会尽可能理解你提交的代码，但不能承诺能够接受，如果你能详细告知我做了什么改变，我会非常感谢。

## 特性

### 公开站点
- 首页展示、作品集列表、大图浏览、作品阐述展示
- Lightbox 大图查看：所有展示模式（single/diptych/wall/report/anthology/archiving）点击图片弹出 Lightbox 大图，支持左右切换、键盘导航（Esc 关闭、← → 切换）、点击遮罩关闭；双联画模式同时展示一对图片，移动端自动上下堆叠；底部展示作品阐述（Markdown 渲染）
- 第五种展示方式「合集（anthology）」：作品集首页以 Grid 网格展示多个合集入口（每个媒体区块对应一个合集，缩略图为该区块的第一张图片），点击入口进入该合集的缩略图页面；每个合集可独立设置标题，标题显示在合集缩略图下方；Grid 布局采用胶卷「接触印相」（Contact Printing）风格，画格固定比例统一排列
- 第六种展示方式「归档（archiving）」：与合集类似支持多个媒体区块和阐述区块，但一级页面以标题列表形式展示（非缩略图网格），标题来源为媒体区块的「合集标题」和阐述区块的「文档标题」；点击标题进入对应区块的二级页面，底部提供「返回上一级」链接
- anthology 和 archiving 媒体区块可选「画幅/展示方式」：支持胶卷画幅比例（3:2/135、2:3/Half、2.7:1/X-Pan、4:3/6x4.5、1:1/6x6、1.16:1/6x7、1.37:1/6x8、2.25:1/6x12、3:1/6x17、5:4/4x5）与展示方式（单幅瀑布流 single、双联画 diptych、照片墙 wall、报告 report）两种维度；子页（`/:slug/:blockId`）与大图页（`/:slug/:filename_large?block=:id`）按区块级展示方式渲染，画幅比例仅影响单幅瀑布流下的画格比例与竖图旋转；其他展示类型固定为对应的展示方式且不可选

### 后台管理
- 登录认证、用户管理、首页素材管理、作品集管理
- 媒体上传（新照片自动置于区块首位）、排序、草稿与发布流程
- 作品阐述文本框支持直接上传图片/视频：上传后保存到 `content/media_library/`，经 sharp/ffmpeg 处理后自动在光标位置插入 Markdown 引用；没有任何文本框引用的文件会被自动清理
- 区块化内容编辑：作品阐述区块与媒体管理区块独立展示，可折叠、可拖拽排序、可通过"上一层/下一层"按钮调整顺序；每个媒体区块可独立上传图片/视频
- 新建作品集自动创建默认媒体区块和阐述区块；所有类型均可添加/删除媒体区块，report/anthology/archiving 类型允许添加多个媒体区块，其他类型限制一个
- 媒体区块与文本区块配置区统一布局：均采用「配置面板（标题 + 画幅/展示方式 + 上传区）→ 主编辑区 → 底部操作栏」三段式结构；文本区块画幅/展示方式固定为「文本模式下不可选」并禁用，「保存文本」按钮与媒体区块「保存顺序」按钮位置对齐
- 后台区块卡片和作品集排序卡片仅通过拖动手柄（⠿）拖动排序，避免编辑文字时误触拖动

### 作品集可见性控制
| 开关        | 效果                                       |
| --------- | ---------------------------------------- |
| **隐藏入口**  | 作品集不在公开导航中显示                             |
| **禁止访问**  | 作品集 slug 页、大图页和相关 API 返回 404（自动联动启用隐藏入口） |
| **隐藏信息**  | 页脚隐藏完整站点信息                               |
| **显示简署名** | 仅在隐藏信息时生效；显示 `shortSignature` 文本         |

### 媒体处理
- **图片处理**：通过 Sharp 自动生成 `thumb`、`medium`、`large` 三种尺寸变体，并对原图进行压缩优化
- **视频转码**：通过 FFmpeg 自动转码为 H.264/AAC MP4 格式，分辨率压缩至 1080p，支持渐进式播放

### 系统设置
- 站点名称、署名、备案号、社交链接、图片/视频处理参数
- 均可在线修改，保存后立即生效，无需重启

### 多语言支持（i18n）
- **前台**：根据浏览器 `Accept-Language` 自动匹配语言（简体中文、繁体中文、英文、日文）
- **后台**：语言可在系统设置页面中手动指定

### 其他特性
- **CDN 加速**：配置 `CDN_URL` 后，媒体 URL 自动拼接 CDN 前缀
- **安全防护**：CSRF 防护、CSP/HSTS 安全头、IP 暴力破解锁定、自定义异常类
- **访问日志**：公开页面 IP/路径/时间戳自动记录，超限自动清理
- **Session 持久化**：Session 存储于 SQLite，服务重启后登录态不丢失
- **优雅关闭**：连接跟踪、健康/就绪检查、404/500 兜底
- **自动化测试**：91 个集成测试 + 11 个单元测试，覆盖核心工作流、安全防护与边界条件，包含 anthology / archiving 二级路由与区块级 `media_format` 渲染

## 作品集展示样式使用指南

系统提供 6 种作品集展示样式。可以先把它们分为两类：

- **直接展示型**：单幅、双联画、照片墙、作品报告
- **目录分层型**：合集、归档

### 快速选择

| 样式 | 展示特点 | 推荐用途 |
| --- | --- | --- |
| **单幅（single）** | 保留媒体原始比例，以带间距的瀑布流排列 | 摄影、绘画、插画等通用作品集 |
| **双联画（diptych）** | 按后台顺序，每两件作品组成一组 | 对照、呼应、前后关系或成组创作 |
| **照片墙（wall）** | 多列无间距连续铺开 | 数量较多、强调密度和整体氛围的系列 |
| **作品报告（report）** | 图片画廊和文字区块混合编排 | 项目记录、展览报告和研究型创作 |
| **合集（anthology）** | 先显示封面网格，再进入各个子系列 | 一个作品集包含多个视觉系列 |
| **归档（archiving）** | 先显示标题列表，再进入具体内容 | 年份归档、文献、手稿和项目资料库 |

如果仍然无法确定，可以按下面的方法选择：

- 没有特殊编排要求：选择**单幅**
- 作品必须两件一起观看：选择**双联画**
- 希望大量图片形成整体冲击：选择**照片墙**
- 需要一边展示一边解释：选择**作品报告**
- 包含多个子系列，而且封面很重要：选择**合集**
- 内容需要按照标题、年份或文档查找：选择**归档**

### 六种样式的区别

#### 1. 单幅（single）

每件作品独立显示，保留原始横竖比例，并以带间距的多列瀑布流排列。大屏通常显示三列，中等屏幕两列，手机一列。

适合没有明确配对关系、希望观众逐件浏览的作品。虽然名称叫“单幅”，但并不表示一个页面只能放一张图片。

#### 2. 双联画（diptych）

系统按照后台媒体顺序自动配对：第 1 件和第 2 件一组，第 3 件和第 4 件一组，以此类推。如果媒体总数是奇数，最后一件会单独显示。

大图浏览时同样以一对作品为一组，移动端会改为上下排列。使用前应先确定作品配对，再调整媒体顺序；插入或移动一件媒体，可能改变后面所有配对关系。

#### 3. 照片墙（wall）

图片以无间距的多列布局连续铺开。大屏通常显示四列，中等屏幕三至两列，手机一列。视频会在照片墙中自动静音循环播放。

照片墙强调整体节奏和视觉密度，不适合需要大量留白、逐件阅读或严格配对的作品。

#### 4. 作品报告（report）

图片和文字可以作为多个区块混合排列，例如“项目介绍 → 图片组 → 创作过程 → 图片组 → 总结”。图片区块较少时按图片数量分列，多张图片通常显示为方形画廊缩略图，点击后可以查看完整大图。

文字区块支持 Markdown，也可以直接上传图片或视频并插入正文。适合展览记录、研究过程、驻留项目、行为艺术和需要上下文说明的作品。

#### 5. 合集（anthology）

合集采用两级结构。一级页面显示多个封面入口，点击封面后进入对应子系列。每个媒体区块代表一个子系列：

- 区块中的第一件媒体自动成为封面
- “合集标题”显示在封面下方
- 没有媒体的区块不会成为入口
- 文字区块不会成为封面入口，而是显示在合集首页的封面网格之后

使用合集时，应为每个媒体区块填写标题，并把最适合作为封面的作品排在第一位。

#### 6. 归档（archiving）

归档同样采用两级结构，但一级页面不展示封面，只显示标题列表。媒体区块使用“合集标题”，文字区块使用“文本标题”，两者都可以成为归档入口；没有标题的区块不会出现在一级列表中。

归档适合按照年份、项目、媒介或文献名称组织内容。它和合集的核心区别是：**合集依靠封面识别，归档依靠标题查找。**

### 合集和归档的区块展示设置

只有合集和归档可以为每个媒体区块单独设置“画幅/展示方式”。这属于区块级设置，不是作品集类型。

“展示方式”包括：

- 单幅瀑布流（single）
- 双联画（diptych）
- 照片墙（wall）
- 报告（report）

“画幅”包括：`3:2 (135)`、`2:3 (Half)`、`2.7:1 (X-Pan)`、`4:3 (6x4.5)`、`1:1 (6x6)`、`1.16:1 (6x7)`、`1.37:1 (6x8)`、`2.25:1 (6x12)`、`3:1 (6x17)`、`5:4 (4x5)`。

选择“展示方式”时，子页按照对应布局展示；选择具体画幅时，子页会显示为统一比例的接触印相式网格。图片方向与画幅方向不一致时，系统可能自动旋转图片以匹配画幅。

### 后台创建与发布流程

1. 在后台添加作品集，填写名称、Slug 和作品集类型。新作品集默认隐藏入口。
2. 进入“媒体管理”。系统会自动创建一个图片区块和一个文字区块。
3. 在图片区块上传图片或视频，并拖动调整媒体顺序。新上传的媒体默认放在区块前面。
4. 编辑文字区块。文本支持 Markdown，也可以上传媒体并插入文本。
5. 使用合集或归档时，为每个区块填写标题，并设置媒体区块的画幅或展示方式。
6. 拖动区块或使用“上一层/下一层”调整页面顺序。
7. 点击“发布更新”，将媒体、文字、标题、画幅和排序同步到前台。
8. 通过 `/<slug>` 地址检查页面，确认后再在作品集卡片中点击“显示入口”。

单幅、双联画和照片墙通常只使用一个媒体区块；作品报告、合集和归档可以添加多个媒体区块。所有类型都可以添加多个文字区块。

### 发布、访问与查看大图

- **隐藏入口**：作品集不在公开导航中出现，但知道地址的人仍然可以访问。
- **禁止访问**：作品集地址、大图页面和相关 API 返回 404，用于真正停止外部访问。
- **发布更新**：媒体、文字、区块标题、画幅和排序只有发布后才出现在前台。
- **修改作品集类型**：类型修改会直接影响前台，不经过作品集内部的草稿发布流程。

修改已有作品集类型不会自动删除内容，但原来的区块结构可能不适合新样式。修改后应立即检查前台，尤其是从合集、归档或作品报告切换到单幅、双联画、照片墙时。

所有直接展示页面以及合集、归档的子页都支持点击作品查看 Lightbox 大图。可以使用左右按钮或键盘方向键切换，按 `Esc` 关闭，点击遮罩返回；单件作品的阐述会显示在大图下方。

## 运行要求

- Node.js `>= 18.17`
- npm `>= 9`
- FFmpeg 和 FFprobe

## 快速开始

### 一键启动（推荐）

macOS / Linux：
```bash
./start.sh
```

Windows：
```cmd
start.bat
```

启动脚本会自动完成以下操作：
1. 检测 Node.js 版本（如未安装则提示安装方式）
2. 自动创建 `.env`（从 `.env.example` 模板生成，含随机密钥）
3. 自动安装依赖（`npm install`）
4. 检测 FFmpeg/FFprobe 可用性
5. 启动服务

### 手动步骤

1. 安装依赖
```bash
npm install
```
2. 启动服务
```bash
npm start        # 生产环境
npm run dev      # 开发环境
```

> `.env` 文件会在首次启动时自动从 `.env.example` 创建并生成随机密钥，无需手动复制。

默认监听 `http://localhost:3000`

管理后台登录地址 `http://localhost:3000/admin/login`

默认管理员账号密码 `admin` / `admin`

## 部署

### 生产环境检查清单

- 使用反向代理（Nginx / Caddy），并设置 `TRUST_PROXY=true`
- 配置 SSL/TLS 证书，启用 HTTPS（可使用 [Let's Encrypt](https://letsencrypt.org/) 免费获取）
- 使用进程管理器（PM2 / systemd），确保异常退出后自动拉起
- 修改 `.env` 中的 `SESSION_SECRET` 为高强度随机值
- 首次登录后立即修改默认管理员密码
- 定期备份：SQLite 数据库、`content/` 目录、`.env` 配置文件

### PM2

```bash
pm2 start server.js --name art-media-publishing-site
pm2 save
pm2 startup
```

### systemd

[Unit]

### Nginx 反向代理

以下为 HTTP 示例，生产环境建议在 Nginx 层配置 HTTPS（可借助 `certbot` 自动管理证书）。

```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        client_max_body_size 350m;
    }
}
```

## 已知边界

- Session 持久化到 SQLite，多实例共享仍需额外方案
- 媒体存储于本地文件系统，云对象存储需进一步抽象
- 视频处理依赖 `ffmpeg`/`ffprobe`，`npm install` 时会自动下载内置二进制；如系统已安装也可直接使用，或通过 `FFMPEG_PATH`/`FFPROBE_PATH` 环境变量指定路径
- 启用 CDN 后，修改 Nginx 配置需手动刷新 CDN 缓存
