# Art Media Publishing Site

[简体中文](README.md) | [繁體中文（香港）](README.zh-HK.md) | [繁體中文（臺灣）](README.zh-TW.md) | [日本語](README.ja.md) | [English](README.en.md)

## 關於這個專案

這是一個基於 Node.js、Express、SQLite 和 EJS 的作品展示與媒體發佈平台。支援圖片、影片、文字等多種形式，包含完整的後台發佈工作流程、圖片變體生成和影片轉碼能力。

## 為什麼會有這個專案

我是一名創作愛好者。

構建這個系統的初衷，起初是因為我自身對商業平台僵硬的展示方式（不是九宮格就是1:1）感到不滿和束縛，同時也對於主流藝術界對「什麼是藝術」這一定義的壟斷，以及由此衍生出的對個人創作者的排擠感到無奈。

於是我透過 AI 的協助，構建了這個系統。起初這只是根據我個人的使用和展示習慣進行設計的東西，但我現在將其開源，希望各位同樣苦於演算法和學術壟斷的個人創作者都能擁有屬於自己的「白盒子」，解構「藝術作品必須依附於特定機構才能呈現」的論述。

由於我本人並非科班出身的軟件工程師，僅具備基本的伺服器維運經驗，所以我可能沒有辦法對當前系統進行進一步的優化或擴展。但我非常歡迎各位對此有需求或共鳴的朋友 fork 或使用這個專案，以滿足自己的需求。

對於 Issues，我會盡可能回覆，但不能承諾能夠解決。

對於 PR，我會盡可能理解你提交的程式碼，但不能承諾能夠接受，如果你能詳細告知我做了什麼改變，我會非常感謝。

## 特性

### 公開站點
- 首頁展示、作品集列表、大圖瀏覽、作品闡述展示
- Lightbox 大圖查看：所有展示模式（single/diptych/wall/report/anthology/archiving）點擊圖片彈出 Lightbox 大圖，不再跳轉新頁面；支持左右切換、鍵盤導航（Esc 關閉、← → 切換）、點擊遮罩關閉；雙聯畫模式同時展示一對圖片，移動端自動上下堆疊；底部展示作品闡述（Markdown 渲染）
- 第五種展示方式「合集（anthology）」：作品集首頁以 Grid 網格展示多個合集入口（每個媒體區塊對應一個合集，縮圖為該區塊的第一張圖片），點擊入口進入該合集的縮圖頁面；每個合集可獨立設定標題，標題顯示在合集縮圖下方；Grid 佈局採用底片「接觸印相」（Contact Printing）風格，畫格固定比例統一排列
- 第六種展示方式「歸檔（archiving）」：與合集類似支援多個媒體區塊和闡述區塊，但一級頁面以標題列表形式展示（非縮圖網格），標題來源為媒體區塊的「合集標題」和闡述區塊的「文檔標題」；點擊標題進入對應區塊的二級頁面，底部提供「返回上一級」連結
- anthology 和 archiving 媒體區塊可選「畫幅/展示方式」：支援底片畫幅比例（3:2/135、2:3/Half、2.7:1/X-Pan、4:3/6x4.5、1:1/6x6、1.16:1/6x7、1.37:1/6x8、2.25:1/6x12、3:1/6x17、5:4/4x5）與展示方式（單幅瀑布流 single、雙聯畫 diptych、照片牆 wall、報告 report）兩種維度；子頁（`/:slug/:blockId`）與大圖頁（`/:slug/:filename_large?block=:id`）按區塊級展示方式渲染，畫幅比例僅影響單幅瀑布流下的畫格比例與豎圖旋轉；其他展示類型固定為對應的展示方式且不可選

### 後台管理
- 登入認證、使用者管理、首頁素材管理、作品集管理
- 媒體上傳、排序、草稿與發佈流程
- 作品闡述文字框支援直接上傳圖片/影片：上傳後儲存到 `content/media_library/`，經 sharp/ffmpeg 處理後自動在游標位置插入 Markdown 引用；沒有任何文字框引用的檔案會被自動清理
- 區塊化內容編輯：作品闡述區塊與媒體管理區塊獨立展示，可折疊、可拖曳排序、可透過「上一層/下一層」按鈕調整順序；每個媒體區塊可獨立上傳圖片/影片
- 媒體區塊與文本區塊配置區統一佈局：均採用「配置面板（標題 + 畫幅/展示方式 + 上傳區）→ 主編輯區 → 底部操作欄」三段式結構；文本區塊畫幅/展示方式固定為「文本模式下不可選」並禁用，「儲存文本」按鈕與媒體區塊「儲存順序」按鈕位置對齊

### 作品集可見性控制
| 開關        | 效果                                       |
| --------- | ---------------------------------------- |
| **隱藏入口**  | 作品集不在公開導航中顯示                             |
| **禁止存取**  | 作品集 slug 頁、大圖頁和相關 API 回傳 404（自動聯動啟用隱藏入口） |
| **隱藏資訊**  | 頁尾隱藏完整站點資訊                               |
| **顯示簡署名** | 僅在隱藏資訊時生效；顯示 `shortSignature` 文字         |

### 媒體處理
- **圖片處理**：透過 Sharp 自動生成 `thumb`、`medium`、`large` 三種尺寸變體，並對原圖進行壓縮優化
- **影片轉碼**：透過 FFmpeg 自動轉碼為 H.264/AAC MP4 格式，分辨率壓縮至 1080p，支援漸進式播放

### 系統設定
- 站點名稱、署名、備案號、社交連結、圖片/影片處理參數
- 均可線上修改，儲存後立即生效，無需重新啟動

### 多語言支援（i18n）
- **前台**：根據瀏覽器 `Accept-Language` 自動匹配語言（簡體中文、繁體中文、英文、日文）
- **後台**：語言可在系統設定頁面中手動指定

### 其他特性
- **CDN 加速**：設定 `CDN_URL` 後，媒體 URL 自動拼接 CDN 前綴
- **安全防護**：CSRF 防護、CSP/HSTS 安全標頭、IP 暴力破解鎖定、自訂異常類別
- **存取日誌**：公開頁面 IP/路徑/時間戳自動記錄，超限自動清理
- **Session 持久化**：Session 儲存於 SQLite，服務重新啟動後登入態不遺失
- **優雅關閉**：連線追蹤、健康/就緒檢查、404/500 兜底
- **自動化測試**：91 個整合測試 + 11 個單元測試，覆蓋核心工作流程、安全防護與邊界條件，包含 anthology / archiving 二級路由與區塊級 `media_format` 渲染

## 作品集展示樣式使用指南

系統提供 6 種作品集展示樣式。可以先把它們分為兩類：

- **直接展示型**：單幅、雙聯畫、照片牆、作品報告
- **目錄分層型**：合集、歸檔

### 快速選擇

| 樣式 | 展示特點 | 建議用途 |
| --- | --- | --- |
| **單幅（single）** | 保留媒體原始比例，以帶間距的瀑布流排列 | 攝影、繪畫、插畫等通用作品集 |
| **雙聯畫（diptych）** | 按後台順序，每兩件作品組成一組 | 對照、呼應、前後關係或成組創作 |
| **照片牆（wall）** | 多欄無間距連續鋪開 | 數量較多、強調密度和整體氛圍的系列 |
| **作品報告（report）** | 圖片畫廊和文字區塊混合編排 | 專案記錄、展覽報告和研究型創作 |
| **合集（anthology）** | 先顯示封面網格，再進入各個子系列 | 一個作品集包含多個視覺系列 |
| **歸檔（archiving）** | 先顯示標題列表，再進入具體內容 | 年份歸檔、文獻、手稿和專案資料庫 |

如果仍然無法確定，可以按以下方法選擇：

- 沒有特殊編排要求：選擇**單幅**
- 作品必須兩件一起觀看：選擇**雙聯畫**
- 希望大量圖片形成整體衝擊：選擇**照片牆**
- 需要一邊展示一邊解釋：選擇**作品報告**
- 包含多個子系列，而且封面很重要：選擇**合集**
- 內容需要按照標題、年份或文檔查找：選擇**歸檔**

### 六種樣式的分別

#### 1. 單幅（single）

每件作品獨立顯示，保留原始橫豎比例，並以帶間距的多欄瀑布流排列。大螢幕通常顯示三欄，中等螢幕兩欄，手機一欄。

適合沒有明確配對關係、希望觀眾逐件瀏覽的作品。雖然名稱叫「單幅」，但並不表示一個頁面只能放一張圖片。

#### 2. 雙聯畫（diptych）

系統按照後台媒體順序自動配對：第 1 件和第 2 件一組，第 3 件和第 4 件一組，如此類推。如果媒體總數是奇數，最後一件會單獨顯示。

大圖瀏覽時同樣以一對作品為一組，流動裝置會改為上下排列。使用前應先確定作品配對，再調整媒體順序；插入或移動一件媒體，可能改變後面所有配對關係。

#### 3. 照片牆（wall）

圖片以無間距的多欄佈局連續鋪開。大螢幕通常顯示四欄，中等螢幕三至兩欄，手機一欄。影片會在照片牆中自動靜音循環播放。

照片牆強調整體節奏和視覺密度，不適合需要大量留白、逐件閱讀或嚴格配對的作品。

#### 4. 作品報告（report）

圖片和文字可以作為多個區塊混合排列，例如「專案介紹 → 圖片組 → 創作過程 → 圖片組 → 總結」。圖片區塊較少時按圖片數量分欄，多張圖片通常顯示為方形畫廊縮圖，點擊後可以查看完整大圖。

文字區塊支援 Markdown，也可以直接上傳圖片或影片並插入正文。適合展覽記錄、研究過程、駐留專案、行為藝術和需要上下文說明的作品。

#### 5. 合集（anthology）

合集採用兩級結構。一級頁面顯示多個封面入口，點擊封面後進入對應子系列。每個媒體區塊代表一個子系列：

- 區塊中的第一件媒體自動成為封面
- 「合集標題」顯示在封面下方
- 沒有媒體的區塊不會成為入口
- 文字區塊不會成為封面入口，而是顯示在合集首頁的封面網格之後

使用合集時，應為每個媒體區塊填寫標題，並把最適合作為封面的作品排在第一位。

#### 6. 歸檔（archiving）

歸檔同樣採用兩級結構，但一級頁面不展示封面，只顯示標題列表。媒體區塊使用「合集標題」，文字區塊使用「文本標題」，兩者都可以成為歸檔入口；沒有標題的區塊不會出現在一級列表中。

歸檔適合按照年份、專案、媒介或文獻名稱組織內容。它和合集的核心分別是：**合集依靠封面識別，歸檔依靠標題查找。**

### 合集和歸檔的區塊展示設定

只有合集和歸檔可以為每個媒體區塊單獨設定「畫幅/展示方式」。這屬於區塊級設定，不是作品集類型。

「展示方式」包括：

- 單幅瀑布流（single）
- 雙聯畫（diptych）
- 照片牆（wall）
- 報告（report）

「畫幅」包括：`3:2 (135)`、`2:3 (Half)`、`2.7:1 (X-Pan)`、`4:3 (6x4.5)`、`1:1 (6x6)`、`1.16:1 (6x7)`、`1.37:1 (6x8)`、`2.25:1 (6x12)`、`3:1 (6x17)`、`5:4 (4x5)`。

選擇「展示方式」時，子頁按照對應佈局展示；選擇具體畫幅時，子頁會顯示為統一比例的接觸印相式網格。圖片方向與畫幅方向不一致時，系統可能自動旋轉圖片以配合畫幅。

### 後台建立與發佈流程

1. 在後台新增作品集，填寫名稱、Slug 和作品集類型。新作品集預設隱藏入口。
2. 進入「媒體管理」。系統會自動建立一個圖片區塊和一個文字區塊。
3. 在圖片區塊上傳圖片或影片，並拖曳調整媒體順序。新上傳的媒體預設放在區塊前面。
4. 編輯文字區塊。文本支援 Markdown，也可以上傳媒體並插入文本。
5. 使用合集或歸檔時，為每個區塊填寫標題，並設定媒體區塊的畫幅或展示方式。
6. 拖曳區塊或使用「上一層/下一層」調整頁面順序。
7. 點擊「發佈更新」，將媒體、文字、標題、畫幅和排序同步到前台。
8. 透過 `/<slug>` 地址檢查頁面，確認後再在作品集卡片中點擊「顯示入口」。

單幅、雙聯畫和照片牆通常只使用一個媒體區塊；作品報告、合集和歸檔可以新增多個媒體區塊。所有類型都可以新增多個文字區塊。

### 發佈、存取與查看大圖

- **隱藏入口**：作品集不在公開導航中出現，但知道地址的人仍然可以存取。
- **禁止存取**：作品集地址、大圖頁面和相關 API 回傳 404，用於真正停止外部存取。
- **發佈更新**：媒體、文字、區塊標題、畫幅和排序只有發佈後才出現在前台。
- **修改作品集類型**：類型修改會直接影響前台，不經過作品集內部的草稿發佈流程。

修改已有作品集類型不會自動刪除內容，但原來的區塊結構可能不適合新樣式。修改後應立即檢查前台，尤其是從合集、歸檔或作品報告切換到單幅、雙聯畫、照片牆時。

所有直接展示頁面以及合集、歸檔的子頁都支援點擊作品查看 Lightbox 大圖。可以使用左右按鈕或鍵盤方向鍵切換，按 `Esc` 關閉，點擊遮罩返回；單件作品的闡述會顯示在大圖下方。

## 執行要求

- Node.js `>= 18.17`
- npm `>= 9`
- `ffmpeg` 和 `ffprobe`（僅在需要處理影片時必須安裝）

## 快速開始

1. 安裝依賴
```bash
npm install
```
2. 複製環境變數模板
```bash
cp .env.example .env
```
3. 啟動服務
```bash
npm start        # 生產環境
npm run dev      # 開發環境
```

預設監聽 `http://localhost:3000`

管理後台登入地址 `http://localhost:3000/admin/login`

預設管理員帳號密碼 `admin` / `admin`

## 部署

### 生產環境檢查清單

- 使用反向代理（Nginx / Caddy），並設定 `TRUST_PROXY=true`
- 設定 SSL/TLS 證書，啟用 HTTPS（可使用 [Let's Encrypt](https://letsencrypt.org/) 免費取得）
- 使用程序管理器（PM2 / systemd），確保異常退出後自動重新啟動
- 修改 `.env` 中的 `SESSION_SECRET` 為高強度隨機值
- 首次登入後立即修改預設管理員密碼
- 定期備份：SQLite 資料庫、`content/` 目錄、`.env` 設定檔案

### PM2

```bash
pm2 start server.js --name art-media-publishing-site
pm2 save
pm2 startup
```

### systemd

```ini
[Unit]

```

### Nginx 反向代理

以下為 HTTP 範例，生產環境建議在 Nginx 層設定 HTTPS（可借助 `certbot` 自動管理證書）。

```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        client_max_body_size 350m;
    }
}
```

## 已知邊界

- Session 持久化到 SQLite，多實例共享仍需額外方案
- 媒體儲存於本地檔案系統，雲端物件儲存需進一步抽象
- 影片處理依賴系統安裝的 `ffmpeg`/`ffprobe`，需支援 H.264/AAC 編碼
- 啟用 CDN 後，修改 Nginx 設定需手動重新整理 CDN 快取
